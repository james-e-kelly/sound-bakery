Detailed Description

An @r executor that owns one OS thread and runs posted work as soon as it arrives.

There is no load balancing, only a single thread.

The executor knows its thread id and can run coroutines synchronously, if it is already on the executor's thread. Otherwise, @r schedule (on the base) suspends the coroutine and enqueues it.
