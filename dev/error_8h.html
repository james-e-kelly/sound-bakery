Detailed Description

Small, self-describing errors for the C++ engine layer.

The C ABI (all sc_* and sbk_* functions) continues to speak sbk_status. Internally, C++ code carries a sbk::error, which pairs that code with the std::source_location where the failure originated.

sbk::error deliberately holds no owned string: it is trivially copyable and allocation-free, so sbk::result is cheap to return everywhere (important for a games/console runtime, and required for a possible -fno-exceptions build). The human-readable message is logged at the origin (see sbk::make_error / sbk::log_error) rather than carried up the stack.

Errors are logged exactly once, at the point they are first produced. Propagating an existing error up the call stack does not log again, so a single failure yields a single log line.

◆ result

template<class T = void>
using sbk::result = typedef tl::expected<T, error>

The result of a fallible operation: a value of type T, or an sbk::error.

result<void> represents an operation that either succeeds or fails with no value. tl::expected is already marked nodiscard, so ignoring a returned result warns.

Prefer this over the raw sbk_status code for internal C++ code; see error/README.md and the control-flow macros in result.h.
